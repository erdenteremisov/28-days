# 28 дней — личный эксперимент

Mobile-first offline-first PWA. Наблюдение → гипотеза → эксперимент → измерение → вывод.

Никакой регистрации, никакого сервера, никакого AI API. Все данные пользователя
живут в IndexedDB в его браузере и никогда никуда не отправляются.

## Стек и почему он такой

Спецификация предлагала React + TypeScript + Vite. Здесь вместо этого —
**TypeScript, компилируемый напрямую в нативные ES-модули**, без React и без
сборщика (Vite/webpack/etc). Причина простая и практическая: приложению не
нужен виртуальный DOM, роутинг с состоянием или экосистема React — экраны и
IndexedDB прекрасно живут на нативных API браузера. Это даёт то же самое
главное требование задачи, «не усложняй архитектуру»:

- ноль npm-зависимостей в рантайме → нечему сломаться при обновлении пакетов;
- ноль шага сборки для деплоя → папку можно просто загрузить на статический
  хостинг как есть, не запуская `npm run build`;
- TypeScript всё равно используется при разработке (см. `src/`) — типы,
  автодополнение и проверка ошибок компилятором сохраняются, просто результат
  компиляции (`app/`) — обычные `.js`-файлы с `<script type="module">`.

## Структура проекта

```
index.html            — точка входа
manifest.json          — Web App Manifest (installable PWA)
sw.js                   — Service Worker (offline-кеш оболочки приложения, v2)
styles/main.css         — вся вёрстка + светлая/тёмная тема (CSS-переменные)
icons/                  — иконки приложения (192, 512, maskable-512)
src/                    — исходники на TypeScript (редактировать здесь)
  types.ts              — типы данных (DayEntry, Experiment, Stage, MetaData...)
  db.ts                 — вся работа с IndexedDB (единственное место)
  state.ts              — расчёт текущего дня/стадии по дате начала
  theme.ts              — применение светлой/тёмной/системной темы
  scale-icons.ts         — SVG-генераторы для 4 шкал 1–5 (см. ниже)
  nav.ts                — нижняя навигация + hash-роутер
  onboarding.ts          — экран первого запуска (3 вопроса) + заметка о приватности
  ai-prompt.ts           — 4 промпта для AI, дословно как присланы, данные подставляются
  export-import.ts       — экспорт/импорт JSON-резервной копии
  main.ts                — точка входа, роутинг между экранами, применение темы
  screens/
    home.ts               — Главная (+ футер о приватности)
    today.ts              — Сегодня (ежедневный дневник, 4 шкалы-иконки)
    experiment.ts          — Эксперимент
    ai.ts                  — AI (генерация и копирование промпта, точные даты разблокировки)
    summary.ts             — Итог (ответы онбординга, тема, бэкап, сброс)
app/                    — СКОМПИЛИРОВАННЫЙ вывод (.js), его и грузит index.html
tsconfig.json           — конфиг компиляции src → app
```

## Как запустить локально

```bash
npx tsc -p tsconfig.json   # компиляция src → app (нужно после любой правки .ts)
python3 -m http.server 8080   # или npx serve .
```

Открыть `http://localhost:8080`. Service Worker и `manifest.json` требуют
`https://` или `localhost` — для локальной разработки `localhost` подходит без
дополнительной настройки.

## Деплой на бесплатный статический хостинг

Build command — пустой везде, сборки нет:

- **Cloudflare Pages** — "Upload assets" или подключить репозиторий, output directory `/`.
- **Vercel** — `vercel`, framework preset "Other", output directory `.`.
- **Netlify** — перетащить папку в Netlify Drop, publish directory `.`.
- **GitHub Pages** — запушить в ветку, включить Pages для корня.

Единственное требование — HTTPS (для Service Worker и installability), все
перечисленные хостинги дают его по умолчанию.

## Что нового в этой версии (по итогам обсуждения)

### 1. Четыре шкалы вместо слайдеров 1–10

Энергия и удовлетворённость дня были слайдерами 1–10 — теперь это тап-кнопки
1–5 с иконками, плюс два новых поля того же типа:

| Шкала | Что измеряет | Иконка | Направление |
|---|---|---|---|
| Энергия | уровень энергии за день | фигура человека (от поникшей до победной позы) | больше = лучше |
| Удовлетворённость днём | насколько день ощущался хорошим | круглое лицо (от грустного до радостного) | больше = лучше |
| Насколько ты выспался? | субъективное качество сна — **отдельно** от часов сна | батарейка (от почти пустой до полной) | больше = лучше |
| Напряжение за день | уровень стресса/напряжения | линия (от ровной до острых пиков) | больше = более напряжённо |

Почему 1–5, а не 1–10: у пяти уровней с иконками нет скрытой точности, которой
на самом деле нет у слайдера — человек физически не различает разницу между
«6 из 10» и «7 из 10» энергии стабильно. У каждой шкалы — своё визуальное
семейство иконок специально, чтобы вопросы не сливались в один и тот же
«как дела в целом» в голове у отвечающего.

«Насколько ты выспался» — это отдельная метрика от часов сна: 8 часов с
частыми пробуждениями и 8 часов непрерывного сна дают одинаковое число в
"Сон, ч", но разное состояние — теперь это видно в данных, а не теряется.

Пока это все обязательные поля (без них AI-промпты, которые прицельно строят
анализ вокруг энергии/удовлетворённости/сна/напряжения, останутся пустыми).

### 2. Четыре AI-промпта — подставлены дословно как присланы

`ai-prompt.ts` больше не содержит собственных упрощённых промптов — это
точные тексты для недели 1, недели 2 (дни 1–14, с явным разделением "до
эксперимента" / "во время эксперимента"), недели 3 (дни 1–21, оба
эксперимента) и финального интервью (дни 1–28). Единственное, что генерируется
дополнительно — «Первичные аналитические наблюдения» в финальном промпте:
приложение не сохраняет тексты ответов AI за предыдущие недели, поэтому вместо
пустого поля туда подставляется честно посчитанная локально сводка по стадиям
(средние энергия/удовлетворённость/напряжение по каждой из 4 стадий) с пометкой,
что это не AI-анализ, а локальная арифметика.

### 3. Приватность — на видном месте, а не только в настройках

Строка «Все данные хранятся только на этом устройстве и никуда не
отправляются» теперь на экране первого запуска (до того как человек начнёт
печатать личное) и тихим футером внизу Главной — раньше это было только в
Итог → Данные, куда можно было и не дойти.

### 4. Кнопка «следующий день» больше не мёртвая

Раньше кнопка "›" была `disabled` без объяснений, если пытаться заглянуть в
будущее. Теперь она всегда активна: если день ещё не наступил, открывается
понятный экран "Этот день ещё не наступил. Он откроется 23 сентября, после
полуночи по времени твоего устройства" — с точной календарной датой. Дата
теперь также всегда видна и для текущего дня ("Сегодня, 17 сентября"), а не
только для прошлых дней. В AI и на карточках экспериментов везде, где раньше
был абстрактный "День 7", теперь показывается и точная календарная дата.

### 5. Ответы онбординга — видны и редактируемы

Итог → «Твои ответы при старте» показывает все три ответа с кнопкой
"Изменить" — раньше это было write-only (записали один раз и негде посмотреть
или поправить). Правка сразу учитывается в следующих AI-промптах (они каждый
раз собираются заново из текущих данных); рядом есть уточнение, что уже
скопированные ранее промпты это не затронет.

### 6. Тёмная тема

Итог → «Оформление»: Системная / Светлая / Тёмная, хранится в базе и
применяется при следующей загрузке. Вся палитра идёт через CSS-переменные, тёмный
вариант — тёплый тёмно-грифельный, а не чистый чёрный/белый, чтобы сохранить
тот же спокойный характер, что и у светлой темы.

### 7. Бонусом (не обсуждали явно, но нашли по ходу работы)

- **«Начать эксперимент заново»** в Итоге — полная очистка данных с двойным
  подтверждением, на случай если кто-то тестировал приложение и хочет начать
  «по-настоящему» с чистого Дня 1.
- **Починен баг**: повторный тап по уже открытой вкладке нижней навигации не
  обновлял экран (например, номер текущего дня мог зависнуть, пока не
  переключишься на другую вкладку и обратно) — теперь любой тап по вкладке
  гарантированно перерисовывает экран заново.

## Проверенные сценарии

Всё выше прогнано через headless Chromium (Playwright, эмуляция iPhone 13)
поверх локального сервера — включая обязательные 10 сценариев из
первоначального ТЗ (первый запуск, персистентность после reload, отсутствие
дублей при редактировании, разблокировка AI-анализа по дням, пропущенные дни,
пустые опциональные поля, экспорт→очистка→импорт, offline-режим после
активации Service Worker, генерация и копирование AI-промпта) плюс отдельно:

- Все 4 новые шкалы (энергия/удовлетворённость/сон/напряжение) корректно
  сохраняются и попадают в промпты как `значение/5`.
- Батарейка для "насколько выспался" визуально проверена на всех 5 уровнях
  после починки бага с обводкой (изначально все 5 уровней выглядели
  одинаково "полными" из-за слишком тонкой обводки на маленьком размере —
  заменено на заливку с прозрачностью).
- Все 4 промпта (неделя 1/2/3/финал) сгенерированы с реальными 28 днями данных
  и двумя экспериментами — проверено на отсутствие незаполненных `{плейсхолдеров}`,
  наличие разбивки "до/во время" в промпте недели 2 и разбивки по стадиям в
  финальных "аналитических наблюдениях".
- Редактирование ответов онбординга — сохраняется и переживает перезагрузку.
- Тёмная тема — применяется мгновенно, переживает перезагрузку, читаема на
  всех экранах включая новые иконки-шкалы (они используют `currentColor`,
  поэтому подстраиваются под тему автоматически).
- Полный сброс эксперимента — данные полностью очищаются, приложение
  возвращается к экрану первого запуска.
- Офлайн-режим и экспорт/импорт по-прежнему работают с расширенной моделью
  данных (проверено, что новые поля попадают в резервную копию).

Что не проверялось (как и раньше): реальные iOS/Android устройства и нативный
диалог установки PWA на «Домашний экран» — это стоит проверить руками после
деплоя.

## Что пока НЕ реализовано

- Стадия «Закрепление» (дни 22–28) по-прежнему без отдельной сущности —
  открытый вопрос из предыдущего раунда, не решался в этой сессии.
- Иконка/брендинг — всё ещё geometric placeholder.
- Push-напоминания сознательно не делались (обсуждали отдельно — решили пока
  не усложнять и сфокусироваться на качестве данных и промптов).
- Поля "Экранное время" и "Shorts/Reels" по-прежнему не разведены явно в
  подписи (входят ли шортсы в экранное время) — обсуждали, но не факт что уже
  зафиксировано как решение; дайте знать, если нужно поправить формулировку.
- День недели и локальные корреляции (обсуждались как идеи) — не добавлялись,
  так как не были явно подтверждены к реализации.
